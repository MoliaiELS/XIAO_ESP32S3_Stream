# 只测试 LRA 马达：XIAO ESP32S3 + DRV2605L

## 新增：震动后四闪的首次故障记录（DEBUG v3）

v3 新增 `FIRST_ERROR`；保留第一次错误，不让随后停止操作或 d 扫描覆盖现场。上传后确认看到 MOTOR DEBUG v3。LED 含义和接线不变。先断电重启，再用 1 档单次测试，间隔 2 秒观察，不连续重发高档命令。发生错误时先记录 FIRST_ERROR，再发 d；r 会清除旧记录并重新初始化，所以不要先发 r。

- `CHIP_PROTECTION`：`captured_status` 是触发保护时的 STATUS，code=1 表示过流位，2 表示过温位，3 表示两者。此值与随后 d 读取的当前值区分。
- `I2C_WRITE`：寄存器写入失败；reg 指出是启动/幅度设置/停止所用寄存器。
- `I2C_READ_POINTER`：读取寄存器前的地址设置失败。
- `I2C_SHORT_READ`：读取字节数不足，code 为实际收到字节数（通常 0），不是 Wire 错误码。
- I²C 写入/指针写入的 code=2 是地址 NACK、3 是数据 NACK、4 是其他错误、5 是超时。
- `stop_confirmed=0`：停止事务未全部成功，断开驱动电源排查，不能只根据 active=0 认为硬件已停。
- `none`：尚无记录。r/重新上电会开始新记录；p/d 不清除记录。

已有截图显示停止后 STATUS=0xE4、I²C ACK 正常。TI 数据手册 8.6.1 将 bit2 定义为 Reserved；不能据此认定反馈故障。停止后的过温/过流位为 0 也不能排除此前瞬态，尤其过温位读取会清除。旧程序将故障锁存为 fault=1，并拒绝后续脉冲；d 不清故障。该锁定保留，不用自动重试掩盖问题。

如记录为 I²C 错误，可检查震动时驱动板 VIN 是否下跌、供电/地线是否过长、震动是否造成接触不稳；这些是待验证原因，不是已确诊。万用表可能捕捉不到短暂压降。IN/TRIG 未使用时 TI 要求接 GND；之前依据模块示例允许留空的说明不够严谨，实际排障建议断电后将 IN 接驱动板 GND，消除浮空输入，但不能断言它就是这次故障原因。仍保持 VIN=3.3V，不直接改 5V。

请提供 FIRST_ERROR 行，并说明两次 Pulse started 时马达是否实际震动。

## 新增：NOT FOUND 的 LED / I²C 诊断（DEBUG v2）

原版 NOT FOUND 合并了“无法读取 STATUS”和“芯片 ID 不匹配”，并不能直接断定接线错。现在更新同目录程序，重新编译上传即可；新增 `MotorDebug.h` 也要保留。看到 `MOTOR DEBUG v2` 才是新固件。诊断不需要连接 IMU，也不自动震动。

使用 XIAO **USER_LED，GPIO21，低电平亮**，不是充电灯，无需另接 LED。启动时先亮；扫描结束后每 3 秒重复一组短闪：

| 每组闪几次 | 含义 |
| --- | --- |
| 1 | 最近检查通信成功，驱动配置就绪 |
| 2 | 最近扫描中地址 0x5A 无 ACK |
| 3 | 0x5A 有 ACK，但 STATUS 读取失败或芯片 ID 不被支持 |
| 4 | 配置未成功或运行出现故障 |
| 5 | ESP32 Wire.begin 初始化失败 |
| 短暂持续亮 | 当前震动脉冲执行中；启动阶段也会亮 |

灯光反映启动/最近诊断状态与运行故障，不是独立的电源检测，也不代表马达一定已正常运动。运行中改线先断电；重新上电后观察。

**操作：**打开串口 115200，发送 `d`（完整扫描和寄存器读取）；发送 `r` 重新初始化并诊断；发送 `p` 查看状态。马达正在运行时拒绝 d/r，先发送 s，避免扫描延迟停止时刻。开机也会执行一次扫描，错过启动日志时发 d。扫描约几秒内完成，期间闪灯分组可能不规整，以 END DEBUG 后为准。

重点看这些输出：

```text
Wire.begin=OK; idle digital levels: SDA=1 SCL=1 (normally 1,1)
ACK 0x5A
Target 0x5A result=0 (0=ACK, 2=address NACK, 5=timeout)
REG 0x00 = 0x..
DEVICE_ID=7 (expected 7 or 3), overtemp=0 overcurrent=0
```

- **没有 ACK 0x5A / result=2**：没有收到地址应答；暂时与马达类型、频率、IN 悬空无关。用万用表在**驱动板本身**量 VIN–GND 是否约 3.3V，静态 SDA/SCL 是否约 3.3V。数字电平 1 不能替代电压测量。断电后量从 XIAO 焊盘到驱动板焊盘的通断，确认焊盘实际导通、面包板排针接触。若板子引出 EN，量其是否处于使能高电平；所提供原理图中的 EN 已接 VIN。可先断电拆下马达，只测试驱动芯片是否应答。
- **SDA 或 SCL 为 0，或 result=5**：总线可能被拉低/超时，检查上述电压；这不是“没发送震动命令”。
- **扫描出别的地址**：记录完整输出，不要直接把驱动地址改为那个地址；DRV2605L 固定为 0x5A。
- **ACK 0x5A，但 STATUS 读失败**：地址应答成功但寄存器事务失败，保留 pointer write error / read bytes 行以定位。
- **STATUS 可读但 ID 非 7/3**：保留原始十六进制值，并核对芯片表面型号，不能直接删掉 ID 检查继续驱动。
- **ready=1 但不震动**：再测试 1/2/3 并检查马达侧。本阶段才需要分析驱动输出、强度和谐振频率。

正常初始化后，待机 MODE(0x01)=0x40、RTP(0x02)=0、OD_CLAMP(0x17)=0x75、反馈(0x1A)=0xB6、CONTROL3(0x1D)=0x81、周期(0x20)=0x33。故障后的值可能不同。诊断只读取，不会强行绕过检查。

下一步请提供发送 `d` 后从 `MOTOR DEBUG v2` 到 `END DEBUG` 的完整输出，以及 LED 每组闪几次。

打开同目录 **MotorOnlyTest.ino**，这是独立程序，不需要 IMU、RS485、Wi-Fi、摄像头，也不需要额外 Arduino 库。同目录两个 .h 文件保留在原处，IDE 会自动使用。上传会替换板上正在运行的固件，不会改动仓库里的原程序。

## 一、接线（先拔掉 USB，焊好、检查后再供电）

你说的 pin 4/5 在这里指 **板上 D4、D5**，对应芯片 **GPIO5、GPIO6**；不是 GPIO4/GPIO5，更不是 GPIO45。

| XIAO ESP32S3 | DRV2605L | 用途 |
| --- | --- | --- |
| **3V3 / 3.3V-OUT** | **VIN** | 3.3V 供电 |
| **GND** | **GND** | 共地 |
| **D4 / GPIO5** | **SDA** | I²C 数据 |
| **D5 / GPIO6** | **SCL** | I²C 时钟 |
| GND（或驱动板本地 GND） | **IN / TRIG** | 未使用输入按 TI 手册接地，无需占用 GPIO |

马达两根线接驱动板 **OUT+ / Motor+** 和 **OUT− / Motor−**，两根都接驱动输出，不能把其中一根接 GND。LRA 没有 ERM 那样的直流旋转方向；仍按马达标记接 +/−。

按你给的 XIAO 图片，USB 朝上时：**左侧从下往上数第 2 个焊盘是 D5，第 3 个是 D4**；右侧从上往下依次是 VBUS、GND、3.3V-OUT。最终以丝印为准。

```text
电脑 USB ── XIAO ESP32S3
              3V3 ───── VIN   DRV2605L
              GND ───── GND       OUT+ ── 马达一端
         D4/GPIO5 ───── SDA       OUT− ── 马达另一端
         D5/GPIO6 ───── SCL
                        IN ───── GND（驱动板本地接地即可）
```

**关于 IN：**你提供的 Adafruit 接线图确实没有连接 IN，但 TI 芯片手册要求未用 IN 接 GND。本程序仍仅通过 SDA/SCL 控制；排障及正式接线将 IN 接驱动板 GND，无需增加一个 ESP32 GPIO。不要把 IN 接到马达输出。

**VIN 使用 3.3V，不照搬 UNO 图的 5V。**你的驱动板原理图将 SDA/SCL 上拉到 VIN，XIAO 使用 3.3V 逻辑。需要的连接就是 XIAO 到驱动板四根线，加驱动板到马达两根线。

## 二、上传

1. Arduino IDE → 文件 → 打开 → 本目录 `MotorOnlyTest.ino`。
2. 选择开发板 **XIAO_ESP32S3**、对应 USB 端口。
3. 工具 → **USB CDC On Boot → Enabled**。无需配置 Wi-Fi 或安装 Adafruit 库。
4. 点击验证，再点击上传。
5. 打开串口监视器，选 **115200**。本程序接受单字符，行尾有无换行都可以。
6. 如果错过启动提示，发送小写 `p` 查看状态，或 `h` 查看帮助。

正常显示 `DRV2605L: FOUND at 0x5A | ready=1 fault=0 active=0`。这是驱动芯片通信成功，不能单凭这行证明马达已焊好。

## 三、开始震动

上电不自动震动。每次在串口输入框输入**一个字符**后点发送：

| 输入 | 动作 |
| --- | --- |
| `1` | 低强度 32/127，震动 150ms，先测这一档 |
| `2` | 中等强度 64/127，震动 300ms |
| `3` | 较高强度 100/127，震动 300ms |
| `s` | 立即请求停止 |
| `p` | 显示驱动状态 |
| `r` | 重新检测并初始化，保持停止 |
| `h` | 显示帮助 |

每次短震到时自动停止，不需要手动发送 s。不要一次发送 123；这会连续更换当前脉冲。焊接或调整线缆应先断电。

当前配置为 **LRA、200Hz（寄存器量化后约 199.1Hz）、2.5V 峰值上限**，保存在 `HardwareConfig.h`。这是根据你提供的 2.5–3.7Vrms、180–220Hz 资料选择的保守开环联调参数；**2.5V 峰值不等于 2.5Vrms**。低档震感可能很轻，可依次试 2、3。程序暂不使用闭环谐振跟踪或效果库。

## 四、排查

- `NOT FOUND`：检查焊点、VIN=3.3V、GND、D4→SDA、D5→SCL。不要把板名 D4 当成代码数字 4。
- `FOUND` 但不震：确认发送的是字符 1/2/3；检查马达焊点、OUT+/OUT−、是否出现 fault；轻触固定好的马达外壳确认。再依次测试 2、3。
- XIAO 重启：检查短路、供电余量、线缆接触。资料标注马达典型工作电流 100–150mA；不要用 GPIO 供电。
- `fault=1` 或 `STOP FAILED`：断开马达电源检查，修复后重新上电。软件定时停止依赖 ESP32 和 I²C 正常工作，不能在断线后保证停止。
