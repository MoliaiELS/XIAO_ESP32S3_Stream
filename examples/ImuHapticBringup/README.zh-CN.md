# DM-IMU-L1 + DRV2605L 联调说明

打开本目录的 `ImuHapticBringup.ino`。这是仓库内**独立 Arduino sketch**，烧录后运行本联调程序；原来的摄像头/Wi-Fi/TCP 主程序不会同时运行。只需 ESP32 开发板包自带的 `Arduino.h`、`Wire.h`、`HardwareSerial`，无需再安装马达或 IMU 库。

## 1. 协议选择

采用 **RS485 主动输出 → RS485 收发模块 → ESP32 UART1**，IMU 提前通过自身 USB 接电脑配置。

- DM-IMU-L1 支持 USB、RS485、CAN，没有可直接使用的 TTL UART/I²C 接口。RS485 使用厂商自定义协议，**不是 Modbus**。
- 本方案直接接收 float32 四元数和欧拉角；CAN 数据经过 14/16 位压缩映射，且也需要外接 CAN 收发器。
- USB 直连 ESP32 需要 USB Host 硬件/软件，本联调方案保留 XIAO USB 用于上传和串口监视。
- 需要一个 **3.3V 供电、3.3V UART 逻辑、速率支持 115200 的 RS485 模块**，例如采用 MAX3485 的模块。不要使用 RO 输出 5V 的普通 MAX485 板直接连接 ESP32。

## 2. 断电接线

以下均按引脚丝印接线；手册未明确给出线束颜色与连接器针序，不能凭颜色猜测。IMU 上使用 `485 A/B`，不要误用 `CAN H/L`。

### IMU 与 RS485 模块

| 信号 | 连接 |
| --- | --- |
| IMU 电源正端 | 稳定的外部 5V 电源正端；IMU 允许 5–28V，首次用 5V |
| IMU GND | 外部电源负端、收发模块 GND、XIAO GND 共地 |
| IMU 485 A | 收发模块 A |
| IMU 485 B | 收发模块 B |
| 收发模块 VCC | XIAO 3V3 |
| 收发模块 RO / RXD 输出 | XIAO **D7 / GPIO44** |
| 收发模块 `/RE`（低有效） | GND，始终使能接收 |
| 收发模块 DE | GND，始终关闭发送 |
| 收发模块 DI | GND，固定未使用的发送输入 |
| XIAO D6 / GPIO43 | 本接收方案不接线 |

若是自动方向模块，没有 DE、/RE，则按该模块手册接接收输出与供电，确认其 TTL 端为 3.3V。不同模块的 TXD/RXD 命名可能从不同视角定义，应以“模块输出 → ESP32 RX”为准。

RS485 A/B 使用双绞线。按模块手册检查总线两端终端匹配及空闲偏置，通常两端各 120Ω；模块若已有终端，不要重复添加。长线或 CRC 错误持续增加时尤其要检查。短线台架调试也需可靠共地。

IMU **不能用 3.3V 供电**。先用 IMU USB 单独配置，配置完断开该 USB，再改为外部 5V 供电运行，避免未确认供电隔离时同时接入两路电源。外部 IMU 电源只与 XIAO 共地，不把外部 5V 接回 XIAO 5V；XIAO 由自身 USB 供电。

### DRV2605L 与马达

| DRV2605L 引脚 | XIAO / 马达 |
| --- | --- |
| VIN | XIAO **3V3** |
| GND | XIAO GND |
| SDA | XIAO **D4 / GPIO5** |
| SCL | XIAO **D5 / GPIO6** |
| IN/TRIG | GND，本程序通过 I²C 控制 |
| OUT+、OUT− | 马达两根线；两端都不能接 GND |

提供的 MRA154A 原理图中 SDA/SCL 各有 10kΩ 上拉到 VIN，所以这个直接接线方案应使用 **VIN=3.3V**。若以后需要 5V 驱动电源，需同时处理 I²C 电平，不可照此接线直接换成 5V。震动导致 XIAO 重启时，检查供电余量与布线，必要时使用独立稳压 3.3V 马达电源并共地；不要并联两个稳压器输出。

你已确认马达为 **LRA1040-0301，交流脉冲 Z 轴 LRA**。MRA154A 是所提供驱动板资料的标识，不能据此确定马达额定参数。

## 3. 先用达妙上位机设置 IMU

使用工作区 `dm-imu/上位机/DM-IMU-Upper v1.0.0.2.zip` 内的软件。先通过 USB 连接 IMU，选择对应 COM 口，打开并进入设置模式：

1. 输出接口：**485**。
2. 485 模式：**主动输出**。
3. 485 波特率：**115200**，8 数据位、无校验、1 停止位。
4. 输出频率：**100Hz**，即发送间隔 **10ms**。
5. 从机 ID / CAN_ID：**1**。本程序按该 ID 筛选。
6. 打开欧拉角和四元数输出。可关闭加速度、角速度；保留也能解析。
7. **保存参数**，退出设置模式返回正常模式；重新上电确认保存。

100Hz 时只发送姿态约 4200 字节/秒，四类全开约 8000 字节/秒，均可用 115200 的 8N1 链路。不要把 115200 配成四类全开 1000Hz。提高速率时需同时修改 IMU 设置与 `HardwareConfig.h` 的 `IMU_BAUD`。

若使用支持 HEX 发送的 USB 串口助手，可按以下顺序逐条发送**十六进制字节**，各条至少间隔 100ms（这些是 USB 配置命令，不能发到本例只接收的 RS485 链路）：

```text
AA 06 01 0D       进入设置模式
AA 08 01 0D       设置从机 CAN_ID=1
AA 0D 01 01 0D    设置 485 波特率 115200
AA 02 0A 00 0D    设置发送间隔 10ms（小端 uint16）
AA 01 13 0D       开启 485 主动模式
AA 01 16 0D       开启欧拉角
AA 01 17 0D       开启四元数
AA 0A 01 0D       输出接口选择 485
AA 03 01 0D       保存参数
AA 06 00 0D       返回正常模式
```

优先使用上位机读取/确认配置。快捷指令依据 V1.2 手册；旧固件若行为不同，按其匹配版本手册处理，不要自动刷固件。

## 4. Arduino IDE 编译与上传

1. 打开 **本目录** `ImuHapticBringup.ino`，不要把它复制到仓库根目录，否则会与原程序的 `setup/loop` 冲突。
2. 开发板选 **XIAO_ESP32S3**，ESP32 包使用你已安装的版本。工具菜单 **USB CDC On Boot → Enabled**。
3. 选择 XIAO 的 COM 口（不是 IMU 的 COM 口）。本例不需要 Wi-Fi 凭据，也不需要摄像头、PSRAM。
4. 已按你提供的马达资料填入保守联调参数，可直接编译上传；上电默认停止，只有发送 `buzz` 才会震动。也可先不接马达，只验证 IMU。
5. 打开串口监视器：**115200**，行尾选择 **Newline** 或 **Both NL & CR**。若错过启动输出，发送 `status`。
6. 上传失败时关闭其他占用串口的软件；必要时按住 BOOT、短按 RESET、松开 BOOT 后重试。

## 5. 马达参数与震动测试

`HardwareConfig.h` 已根据你提供的马达资料设置：

- `MOTOR_TYPE = MotorType::LRA`，用户提供型号 LRA1040-0301、Z 轴。
- `MOTOR_VOLTAGE_LIMIT = 2.5f`：**峰值电压上限**，不是 2.5Vrms。图片给出额定 2.5–3.7Vrms；此设置保守，实际有效值低于额定范围，初次震感可能偏弱。3.3V 供电也不能保证达到图片所列额定振动量。
- `LRA_FREQUENCY_HZ = 200.0f`：图片给出谐振区间 180–220Hz，选择中间值作为初始值，不代表测得的单体谐振点。按周期寄存器量化后约为 199.1Hz。

图片还给出工作频率 140–300Hz、典型电流 100–150mA（3.0Vrms 谐振点）、线圈电阻 12–18Ω。这里将图片作为用户提供的规格依据；没有独立测量这些参数。若要禁用震动，可把电压设为 0，此时 `configured=0`，IMU 仍照常运行。

采用 **LRA 开环 + RTP**，硬件产生交流驱动，ESP32 给出强度与持续时间。开环频率按寄存器量化，可能略偏于填写值；足以做初次联调，不具备闭环自动谐振跟踪和自动制动。尚未实现 ROM 效果库与闭环校准；没有写入芯片 OTP。

串口命令：

| 命令 | 作用 |
| --- | --- |
| `help` | 命令帮助 |
| `status` | 接收字节数、合法帧数、CRC 错误、姿态新鲜度、驱动状态 |
| `stream off` / `stream on` | 关闭/开启每秒 10 行姿态输出，采集继续 |
| `init` | 重新检测、配置驱动，保持停止；接线变更应先断电 |
| `buzz 32 150` | 较低强度震动 150ms，首次从这一条开始 |
| `buzz 64 300` | 更高强度震动 300ms |
| `stop` | RTP 清零并进入待机 |

强度范围 1–127，时长 1–1000ms；强度是相对于配置的电压上限，不是绝对电压。上电不自动震动，每次命令到时停止。手动震动命令可在 IMU 未连接时使用，便于分开排查。

软件停止依赖 I²C 链路和 ESP32 正常运行；若出现 `fault=1` 或停止写入失败，断开马达电源后排查。计时不是独立硬件断电保护。

## 6. 如何判断成功

IMU 正常时状态显示 `imu=FRESH`，每 100ms 打印一次真实最近样本，例如输出结构：

```text
IMU ms=... q_wxyz=w,x,y,z rpy_deg=roll,pitch,yaw age_ms=四元数年龄,欧拉角年龄
```

- 四元数顺序为 **w,x,y,z**，读取 IMU 自身解算结果；RPY 从寄存器 0x03 直接读取，单位**度**。
- Roll 绕 IMU X 轴、Pitch 绕 Y 轴、Yaw 绕 Z 轴，参考 IMU 外壳/手册坐标，不是 ESP32 板坐标。
- 两类数据是不同帧，`age_ms` 分别表示 ESP32 收到它们以来的时间；协议没有同步采样时间戳，本例不声称严格同步。
- 超过 250ms 没收到任一种姿态帧，停止打印旧姿态，状态变成 `WAIT/STALE`。
- 六轴 IMU 没有磁力计，Yaw 不是绝对罗盘航向，长期会漂移。校准和静置测试时马达应停止；IMU 安装尽量远离震动源。

建议顺序：只接 XIAO 上传 → 只接 IMU 看姿态 → 加驱动板确认 `drv=FOUND` → 填好马达参数、断电焊接马达 → 低强度短脉冲 → 同时转动 IMU 并震动观察。

| 现象 | 优先检查 |
| --- | --- |
| `rx_bytes=0` | IMU 供电、485 主动模式/输出接口、RO→D7、/RE=0 |
| 收到字节但 `frames=0` | 波特率、A/B 极性、ID=1、是否误用 CAN/Modbus |
| `crc_errors` 持续增长 | 共地、终端、供电噪声、线缆、波特率；不会关闭 CRC 来掩盖问题 |
| `frames` 增长但 `WAIT/STALE` | 是否同时打开欧拉角和四元数 |
| `drv=MISSING` | VIN、共地、D4/D5 是否接反，地址固定 0x5A |
| `drv=FOUND configured=0` | 电压/频率仍为 0、越界，或 I²C 配置失败 |
| 震动弱 | 检查额定参数、谐振频率、供电和机械固定；再逐渐提高强度 |

## 7. 文件与验证

- `HardwareConfig.h`：引脚、IMU 通信参数、马达参数。
- `DmImuParser.h`：不依赖 Arduino 的流式解析器；19/23 字节变长帧、小端 float32、CRC16-CCITT-FALSE、ID 筛选、错帧恢复。
- `HapticDriver.h`：DRV2605L I²C 驱动、LRA/ERM 开环配置、限时震动和错误状态。
- `ImuHapticBringup.ino`：接收、串口命令及输出调度。
- `../../tests/dm_imu_parser_test.cpp`：主机侧协议回归测试。它不替代硬件验证。

2026-09-08 软件验证：使用本机已安装的 **esp32:esp32 3.3.11**、开发板 **XIAO_ESP32S3**、USB CDC Enabled 编译通过。g++ 主机测试通过 CRC 标准向量、姿态解码、噪声/错 CRC/错帧尾、ID 筛选、NaN/零四元数拒绝、每个字节位置丢失恢复、半帧超时、载荷内帧头字节、millis 回绕。尚未连接硬件，未声称完成实测。

主机测试（仓库根目录，需 g++）：

```powershell
New-Item -ItemType Directory -Force build
g++ -std=c++11 -Wall -Wextra -Werror tests/dm_imu_parser_test.cpp -o build/dm_imu_parser_test.exe
./build/dm_imu_parser_test.exe
```

原有主驱动的 `ImuSensor`、`CommandHandler`、网络协议仍是原来的实现。这次交付的是可独立验证硬件的新增程序；以后集成时复用解析器和驱动，并在主循环持续轮询、根据 `fresh()` 决定上传数据，不要只在低频上传时读取 UART。
